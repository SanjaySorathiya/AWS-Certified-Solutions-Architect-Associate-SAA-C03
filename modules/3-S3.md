### **S3 — Simple Storage Service (S3)**

S3 is AWS's most versatile object storage service. SAA-C03 exams feature many S3 questions covering security, performance, durability, and cost optimization.

---

#### **1. S3 Storage Classes — SAA-C03 Decision Matrix**

| Storage Class | SAA-C03 Target Use Case | Min Duration | Min Object Size | Retrieval Latency | Cost / Retrieval Fees |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **S3 Standard** | Frequently accessed data, active files | None | None | Milliseconds | Highest storage rate; $0 retrieval fee |
| **S3 Intelligent-Tiering** | Unknown / changing access patterns | None | None (<128KB always in Frequent) | Milliseconds–minutes | Small monitoring fee; auto-shifts; $0 retrieval fee |
| **S3 Standard-IA** | Infrequent access; rapid retrieval needed | 30 days | 128 KB | Milliseconds | Lower storage cost; retrieval fees apply |
| **S3 One Zone-IA** | Infrequent access; can tolerate AZ loss | 30 days | 128 KB | Milliseconds | 20% cheaper than Standard-IA; 1 AZ only |
| **S3 Glacier Instant Retrieval** | Quarterly archives; millisecond access | 90 days | 128 KB | Milliseconds | Low storage rate; retrieval fees apply |
| **S3 Glacier Flexible Retrieval** | Archives; flexible retrieval time OK | 90 days | 40 KB | 1 min – 12 hours | Low-cost storage; higher retrieval latency |
| **S3 Glacier Deep Archive** | Long-term compliance (7–10 yrs) | 180 days | 40 KB | 12 – 48 hours | Lowest-cost storage; highest retrieval latency |
| **S3 Express One Zone** | High-throughput, single-digit ms latency workloads | None | None | Single-digit ms | Highest premium; directory bucket; single AZ |

---

| 💡 TIP: S3 Lifecycle Policies |
| :--- |
| **Automation:** Automates transitions or deletions.<br>**Exam Pipeline:** Standard → Standard-IA (30d) → Glacier (90d) → Deep Archive (365d) → Expire. |

#### **2. S3 Access & Security Control**

| Access Mechanism | Scope | Primary Function | SAA-C03 Exam Indicators |
| :--- | :--- | :--- | :--- |
| **Bucket Policy** | Bucket + Objects | JSON policy attached to bucket | Cross-account access, public bucket enforcement, IP restrictions, HTTPS-only rules |
| **IAM Policy** | Identity | JSON policy on IAM users, groups, roles | Restricting specific internal AWS users/roles |
| **S3 ACLs** (Deprecated) | Object / Bucket | Fine-grained legacy XML access lists | Disable completely via S3 Object Ownership (Bucket owner enforced) |
| **S3 Block Public Access** | Account / Bucket | Centralized override blocking public access | First line of defense; overrides all permissive bucket policies/ACLs |
| **S3 Object Ownership** | Bucket | Specifies owner of uploaded objects | Required when disabling ACLs to simplify ownership rules |
| **VPC Endpoint Policy** | Gateway Endpoint | JSON policy attached to VPC endpoint | Restricting S3 access from VPC to specific buckets without internet |

| ⚠️ EXAM TRAP: S3 Block Public Access |
| :--- |
| **4 Sub-settings:** BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets.<br>**Override Rule:** If any block setting is **ON** at the AWS Account level, it completely overrides bucket-level rules. |

#### **3. S3 Data Encryption Matrix**

| Encryption Type | Key Owner | Management Overhead | SAA-C03 Key Indicator |
| :--- | :--- | :--- | :--- |
| **SSE-S3 (AES-256)** | AWS | **None** (Fully managed by S3) | Default encryption since Jan 2023; "simplest setup" |
| **SSE-KMS** | AWS KMS | **Low** (Custom KMS key policies) | "Audit decrypts" via CloudTrail, "key rotation", "custom keys" |
| **SSE-C** | Customer | **High** (Customer manages external keys) | "Bring your own key"; keys passed via HTTPS headers |
| **Client-Side** | Customer | **Highest** (Customer encrypts before upload) | "Data never plaintext in AWS"; client handles enc/dec keys |
| **DSSE-KMS** | AWS KMS | **Low** (Dual-layer KMS encryption) | "Double encryption", strict defense/gov compliance |

#### **4. S3 Replication Comparison**

| Feature | Cross-Region Replication (CRR) | Same-Region Replication (SRR) |
| :--- | :--- | :--- |
| **Primary Use Cases** | Disaster Recovery (DR), low latency for global users, compliance | Log aggregation, dev/test synchronization, data sovereignty |
| **Versioning** | Required on BOTH source and destination buckets | Required on BOTH source and destination buckets |
| **Existing Objects** | Not auto-replicated; requires **S3 Batch Replication** | Not auto-replicated; requires **S3 Batch Replication** |
| **Delete Markers** | Not replicated by default (requires opt-in) | Not replicated by default (requires opt-in) |
| **Chained Replication** | No (A → B → C is unsupported; requires A → C) | No (Same chaining limitation applies) |

| 💡 TIP: S3 Replication Time Control (RTC) |
| :--- |
| **S3 RTC:** Guarantees 99.99% of objects replicate within 15 minutes. Use for RPO requirements of ≤ 15 mins. |

#### **5. S3 Performance Optimization**

| Optimization Method | Implementation Details | SAA-C03 Scenario Indicator |
| :--- | :--- | :--- |
| **Multipart Upload** | Splits file into parallel chunks; auto-resumes on failure | Recommended for files **> 100 MB**; **REQUIRED** for files **> 5 GB** |
| **S3 Transfer Acceleration** | Routes uploads via AWS Edge Locations + AWS global network | Minimizes latency for distant uploads (e.g., global clients) |
| **Byte-Range Fetches** | Request specific byte chunks in parallel | Accelerates download of large files; retrieves partial file segments |
| **S3 Select / Glacier Select** | Server-side SQL filtering; returns only matching records | Reduces network bandwidth and client-side CPU processing |
| **Prefix Scalability** | Performance scales per prefix: **3,500 PUT/POST/DELETE** and **5,500 GET/HEAD** requests per second | Scale S3 performance by partitioning data using randomized prefixes |

| ⚠️ EXAM TRAP: S3 vs. Shared Filesystems |
| :--- |
| **S3 is Object Storage:** NOT a filesystem; cannot be mounted natively as NFS/SMB. Use **EFS** for shared POSIX filesystems.<br>**SGW S3 File Gateway:** Bridges on-premises servers to S3 as virtual NFS/SMB mount. |

#### **6. Advanced S3 SAA-C03 High-Yield Topics**

| Advanced Feature | Target Mechanism / Rules | Key Exam Scenarios |
| :--- | :--- | :--- |
| **S3 Object Lock** | • **Governance Mode**: Users need `s3:BypassGovernanceRetention` to delete.<br>• **Compliance Mode**: ABSOLUTE lock. No user (including AWS root) can delete.<br>• **Legal Hold**: Indefinite lock; no retention dates. | Compliance, Write-Once-Read-Many (WORM), protection against ransomware / internal rogue deletions. |
| **S3 CORS** | XML configuration allowing resource requests across domains. | Web application hosted on S3 static website (Domain A) needs to pull images/fonts from S3 Bucket B (Domain B). |
| **S3 Versioning** | Once enabled, can only be suspended (not disabled). Generates Unique Version IDs. | Protecting against accidental deletes or overwrites. Enabled with **MFA Delete** for admin-level deletions. |
| **S3 KMS Bucket Keys** | Replaces individual object KMS requests with a bucket-level key. | Reducing AWS KMS costs by up to 99% for heavy-throughput KMS-encrypted S3 buckets. |
